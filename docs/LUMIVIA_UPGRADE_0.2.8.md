## 保留的定制

保留周/月额度扣时重置、自动扣时开关、窗口联动、事务行锁、预览冲突保护、
同组续费、日窗口和 Fork 更新来源。月额度仍沿用 30 天滚动周期。
休闲中心为独立服务，主站提供给它的奖励/订阅分配接口保持兼容。

## 模型智检

- 管理员设置站内/外部 Key、模型、生成参数、定时间隔与公开展示。
- 用户用自己的站内 Key 或外部 HTTPS 接口自测，个人结果默认私有。
- 两种固定测试入口：鹈鹕骑行、按规则抽样的随机创作；保存完整题目和抽样条件。
- 公开作品包含分组、画面通过率、历史状态、截图、动画 HTML、Token、耗时和 TPS。
- 复用全局管理员 API Key 提交检测、等待/轮询、读取结果或下载 WebP；支持 24 小时幂等去重。
- 结论为画面规则初筛，接口/渲染失败单列，不承诺判断真实智商或模型身份。

智检包含 Vue 页面、Go 主站代理及 Node.js/SQLite/Chromium 独立服务。
默认不启用生产入口；主站 `MODEL_CHECK_ENABLED=true` 后通过运行时公开设置显示。
Go 与独立服务的鉴权桥保留会话 IP/UA 绑定，并限制回环通信和可签名的只读接口。
私有 Key、SQLite、加密主密钥、模型作品和本地运行配置不随仓库发布。

完整配置见 [智检部署说明](../extensions/model-check/DEPLOYMENT.md)，
接口用法见 [管理员 API](../extensions/model-check/API.md)。
两个镜像使用同一个完整提交号，CI 发布不会自动改动服务器。

## v0.2.8 数据迁移与回退

相对本次合并基线只新增 `238b`、`239`、`240` 三份迁移。旧迁移原文不变，
迁移框架按完整文件名记录，不与此前的定制 235 冲突。不要重命名或改写已发布的 SQL。

`239_channel_reasoning_effort_multipliers.sql` 将
`groups.model_pricing` 中显式配置的 `max_reasoning_effort_multiplier`
迁移到新的按推理强度计价结构，然后删除旧键。
旧应用只识别旧键，因此执行迁移后**仅切回旧镜像不足以恢复原计价**，
容器健康检查也不能证明计价正确。

正式部署前保留数据库和配置备份，特别是各分组原始定价配置。若升级后回退，
应先核对旧版计价所需字段；在没有新业务写入时可评估恢复配套数据库备份，
已有新写入时应制定按字段兼容恢复或前向修复方案，不能直接覆盖整库。
仓库现有通用更新脚本不会自动完成这类计价数据恢复。

上游还移除了旧 Fable 5.1 max 的隐式 3x 默认值；新的未配置推理倍率为 1x。
显式设置会迁移，依赖旧默认值的站点须在上线前核对各模型/分组倍率。
上述事项是后续部署的兼容性要求，不会在 GitHub 推送时执行数据库操作。
