# Lumivia 0.2.5 升级说明

从 Fork `main` 的 `13e4ee4c6134e93eabc1d5ef9ca9a69b27c35fac` 合并官方
`upstream/main` 的 `881f3202694c6bc932446931a30c27d9675178b9`（版本 0.2.5）。
使用 merge commit 保留双方历史，后续同步仍可识别共同基线。

## 定制保留

- 周限额手动扣时重置、每个订阅独立的自动扣时开关，以及提前跳周同步推进月周期。
- 月额度手动扣时重置、周窗口同步、日窗口保留、预览过期保护和提交后缓存失效。
- `auto_advance_week` 字段、原有迁移、Ent 生成代码、DTO、用户接口及订阅页面。
- Lumivia 发布流程、固定 SHA 镜像更新脚本和 Fork 更新/回退来源。

合并时按文件比较共同基线到 Fork 的定制补丁与官方 0.2.5 到合并结果的补丁，
53 个文件的原有增删内容全部保留。随后仅将监控页面测试中写死的提供商数量
改为 `PROVIDERS.length`，适配上游新增 OpenCode；Grok 默认值及布局断言仍保留。

上游新增管理员订阅批量操作，并将订阅时长调整改为事务内锁行后计算。
该调整与定制周/月扣时使用同一订阅行锁；原有扣时计算和自动推进逻辑保持不变。

## 迁移和回退

- `238_opencode_go_platform.sql` 将四处平台/提供商 CHECK 扩展为包含 OpenCode
  的超集，保留 MiniMax 等现有取值；没有修改订阅表和扣时字段。
- `238_purge_unlimited_user_platform_quotas.sql` 删除日、周、月限额全部为 NULL
  的平台配额行。新版本仅为配置过限额的平台保存记录，不存在的行表示不限额。
- 两份上游迁移共用 238 前缀，但完整文件名不同。迁移框架按完整文件名排序、
  记录主键及校验和，因此无需改名。所有已发布迁移（包括定制 235）内容不变。
- 回退到 0.2.4 时，扩展后的 CHECK 可保留；若已创建 OpenCode 配置，旧应用
  不具备对应功能，回退前须评估。被清理的无限额平台配额行及其周期用量
  不会因回退镜像而恢复，需保留升级前数据库备份；不得自动恢复整库覆盖新写入。

## 发布

合并 PR 后按 [维护说明](LUMIVIA_MAINTENANCE.md) 等待 CI 和 Lumivia 发布成功，
再使用 Fork 的固定 SHA 镜像通过 `deploy/lumivia-update.sh` 备份并部署。
本次源码同步不执行生产部署或修改生产订阅数据。
