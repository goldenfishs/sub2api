# Lumivia upstream acceleration detection

OpenAI accounts are automatically checked for Astra and GPT-6.1 Sol priority (Fast) and ultrafast support. Account model mappings are applied before probing. One worker uses a bounded, deduplicated queue; periodic discovery begins 30 seconds after startup and repeats every 10 minutes. Completed observations expire after 6 hours; transport and HTTP errors expire after 15 minutes. Probes generate small paid upstream requests, never on the downstream request path. Arbitrary downstream model names cannot create additional probe models.

Only a completed response explicitly reporting the requested tier confirms support. HTTP 200, a created event, a missing tier, or a completed default response do not establish accelerated execution. Default/missing are shown as unconfirmed, because some upstreams conceal their effective tier. Explicit unsupported-tier errors are distinguished from authentication, rate-limit and transport failures. Capabilities are scoped to upstream model, tier and credential/endpoint identity. Account edits invalidate observations; tokens and raw upstream errors are not exposed in the capability UI.

For accelerated downstream requests (Responses, Chat Completions, Messages conversion, or WebSocket), the scheduler first considers only accounts with a fresh matching confirmation. Account-specific and group Fast policies determine which tier is checked. Existing model, group, quota, health, retry exclusions and concurrency rules still apply. Eligible queued capacity remains preferred. Only when the preferred scheduler pass finds no available account is a normal pass attempted. Deliberate fallback writes service_tier=default before sending and billing, including WebSocket response.create. Established WebSocket chains cannot silently switch accounts; changes to the requested tier require reconnecting.

Admin account rows show separate Fast and Ultrafast badges. Hover to see model-specific observations; a green aggregate means at least one model is confirmed, not every model. The list's existing refresh controls fetch updated observations. Administrators can queue a check with POST /api/v1/admin/accounts/:id/probe-service-tiers and JSON {"model":"gpt-6-astra"} or {"model":"gpt-6.1-sol"}. The response data contains queued; duplicate pending checks count as queued, full/stopped workers return false. Checks do not change account schedulable/status settings.

GPT-6.1 Sol Ultrafast uses the official 6x multiplier, matching Astra. A successful probe establishes reported tier support, not a guaranteed latency or TPS.

Verification covers classification, expiry and credential invalidation, actual legacy/advanced schedulers with conflicting sticky bindings, exclusions and fallback, policy tier rewrites, ordinary fallback billing, WebSocket turn consistency, bounded queue lifecycle, streaming termination without EOF, mapped upstream request transport/persistence, and Sol Ultrafast pricing. Frontend tests cover badge states and locale completeness; Playwright verified desktop/mobile rendering without browser errors or horizontal overflow.
